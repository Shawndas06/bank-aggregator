# Проверки PR

Workflow `.github/workflows/ci.yml` запускается для каждого push, PR, merge group и вручную. Фильтров путей и пропуска тестов по изменённым файлам нет. Обновление PR отменяет устаревший запуск того же события. В PR GitHub проверяет результат объединения с целевой веткой; push дополнительно запускает проверку, даже когда конфликт мешает событию pull_request.

| Строка GitHub | Что действительно проверяется |
|---|---|
| conflicts | Маркеры конфликтов в tracked текстах и `git merge-tree` с актуальной целевой веткой; на push — с default branch |
| web / typecheck | Оба TypeScript project references через `tsc -b` |
| web / lint | Действующие правила ESLint без подавления старых ошибок |
| web / build | Production-сборка Vite вместе с TypeScript |
| python | Установка зависимостей, pip check, компиляция, undefined names/syntax и базовые тесты |
| calculations | Прогресс накоплений, последовательность взносов, завершение, лимиты: равно/выше порога, ноль, изоляция группы |
| access | Владение целями, запрет пополнения неактивных целей, матрица изменения ролей и защита роли владельца |
| postgres / redis / api | Чистый PostgreSQL 15, запись/повторное чтение, таблицы моделей, Redis, реальный lifespan API, health/OpenAPI и запрос без авторизации |
| dependencies / python | pip-audit production и test requirements, включая транзитивные зависимости; любая известная уязвимость блокирует |
| dependencies / web | npm ci и npm audit всего дерева; high/critical блокируют, остальные видны в отчёте |
| docker / build and smoke | Валидация Compose, сборка двух production-образов, запуск PostgreSQL/Redis/API/nginx, health, HTML/assets/SPA и отсутствие локальных файлов в образах |
| required | Требует `success` всех перечисленных jobs; failure/cancelled/skipped блокируют |

Python test reports сохраняются как JUnit artifacts даже при падении. Код PR выполняется без repository secrets, токен workflow имеет только contents:read; pull_request_target не используется. Docker CI не публикует образы и не использует production-данные. Dependabot еженедельно открывает обновления npm, pip, Docker и Actions.

## Локальный запуск

Node 22.12+ (22.x), Python 3.11, Docker Compose v2:

```sh
cd frontend
npm ci
npm run check
npm run build
npm audit --audit-level=high
```

```sh
cd backend
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
pip check
ruff check --select F821,F822,F823,E9 .
DEBUG=false pytest -m 'not integration'
```

```sh
docker compose -f compose.ci.yml up --build --wait --wait-timeout 180
python3 .github/scripts/docker_smoke.py
docker compose -f compose.ci.yml down --volumes --remove-orphans
```

Integration tests требуют `CI_INTEGRATION=1`, `DATABASE_URL` отдельной одноразовой PostgreSQL и `REDIS_HOST`. Настройки передаются самому backend-процессу, а не только тестовой обёртке. Запускать `pytest -m integration` только на тестовой БД. Каждая job создаёт собственную среду: needs не переносит БД или файлы.

## Защита main

Обязательный check: `required`, strict/up-to-date включён. Успешный агрегатор означает успех каждой отдельной проверки; сами строки остаются видны в PR. Требовать PR и разрешённые обсуждения; запретить force push и удаление main. Применять правила к администраторам. Переименование job требует синхронного обновления branch protection. Workflow-файлы попадут в main только после принятия PR; до этого проверки уже работают на его ветке.

## Как покрывать план развития

CI не может проверить несуществующую реализацию семейного календаря. Для PR по плану добавить тесты настоящего API/сервиса; не создавать параллельный тестовый калькулятор, который приложение не вызывает.

| Область плана | Обязательные сценарии в реализующем PR | Текущее покрытие |
|---|---|---|
| Договорённости и приватность | Приглашение без раскрытия; подтверждение самим участником; прямой API чужим пользователем; отзыв доступа | Базовые сервисные проверки владения целями и ролей; новые соглашения ещё отсутствуют |
| Календарь | 55 000 − 35 000 − 25 000 = −5 000 до позднего дохода; подтверждённый взнос 8 000 до платежа даёт минимум 3 000; отмена возвращает риск | Новый календарь ещё отсутствует |
| Учёт | Копейки/точная арифметика, резерв, запрет кредитного лимита как собственного ресурса, RUB; внутренний перевод нейтрален; оплата и поступивший взнос не учитываются повторно | Протестированы существующие накопления и пороги лимитов; вся банковская аналитика не покрыта |
| Состояния и хранение | Повторы, отмены, перестановки и конкуренция; сохранённая версия одинаково видна обоим участникам после reload | Базовый PostgreSQL roundtrip; новые сущности ещё отсутствуют |
| UI | Два пользователя, три экрана, изменения/отзыв/ошибки через production build | Build/assets/SPA smoke; браузерного E2E пока нет |
| Источники данных | Время обновления и источник; ошибка банка без случайной подмены; воспроизводимые синтетические fixtures | Внешние банки не вызываются в CI; интеграция с банком не доказана |

В backend есть alembic.ini, но нет каталога миграций. Проверка таблиц на чистой БД не заменяет upgrade существующей БД. При появлении миграций добавить отдельную обязательную job с upgrade на пустой и заполненной БД, повторным upgrade и проверкой данных.

## Обнаруженные блокеры исходной версии

При настройке на основе `93fbab3` настоящие TypeScript и ESLint выявили существующие ошибки frontend, аудит зависимостей — известные уязвимости. Они остаются блокирующими, без baseline/ignore/continue-on-error. PR с CI следует держать draft до устранения или осознанного отдельного решения по каждому блокеру. Эти результаты не являются полным аудитом проекта.

Исправлены пропущенный импорт SavingsGoal и локальные импорты settings, мешавшие проверке баланса в платёжном сервисе. Существующие fail-open пути платежей при других сбоях этим PR не устранены.

Локальная .env исключена из Git, встроенные учётные данные убраны из Compose и defaults. Ранее опубликованные credentials остаются в истории и должны быть отозваны/заменены владельцем. Удаление из текущей версии не отзывает их.
